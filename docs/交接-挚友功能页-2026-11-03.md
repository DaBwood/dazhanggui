## 五、必须记住的坑（都踩过）

| 坑 | 结论 |
|---|---|
| `num_children` 打在 FGUIImage 上 | 只有 `FGUIComponent` 有，先 `as FGUIComponent` 判空 |
| `_input` 里 `return` 缩进错 | 会让后面所有按钮静默失效 |
| `var x := TextureRect.new()` 后赋 PanelContainer | 运行时 `Invalid assignment`，要写 `var x: Control` |
| `TextureRect` 默认 EXPAND_KEEP_SIZE | 大图会撑满屏，必须 `EXPAND_IGNORE_SIZE` |
| `Panel.add_theme_stylebox_panel` | 不存在，用 `add_theme_stylebox_override("panel", sb)` |
| 变量名 `tr` | 撞 `Object.tr()`，用 `tr_rect` |
| 新增 png | 必须先 `--headless --import` 再渲染，否则整页空白 |
| 中文注释 `##` 里带「」 | GDScript 解析报错，用 `#` |
| `data/` 下新 json | 不登记会被判「孤儿配置」，加进 `CONFIG_SPECIAL_LOADERS` |

## 7.3 试过并失败的两条路（别再重试）

**① 直接把 `_create_base_popup` 改成固定尺寸 + 整图当 StyleBoxTexture**

```gdscript
var fit_s = minf((vs.x-24)/750.0, (vs.y-60)/781.0)
popup_size = Vector2(750, 781) * fit_s
skin.texture = popup_frame_fixed   # texture_margin 全 0
```

结果：**弹窗背后多出一圈深灰块**（比窗框大一圈），页面没有被整体压暗。

instrument 出来的客观数据（真机 540×960，非 headless）：

```
viewport = 600×1067
popup rect = (12, 233.6) size 576×599.8     ← 尺寸/比例都对
stylebox   = StyleBoxTexture  tex = popup_frame_fixed.png   ← 纹理确实挂上
child VBox rect = (42.7, 269.6) 499×524
```

`mask` 是 `@ColorRect` 600×1067 / z=60、**确实铺满视口**；把 mask 抬到 z=60、纹理边距清零都试过，**截图哈希不变**（说明改的不是问题源）。

**结论**：问题不在“面板被压小”，而在“多个弹窗层 + 遮罩 + 整图 StyleBox”三者叠加时的绘制顺序/尺寸谁覆盖谁，没定位到就不再动这 113 处调用。

**② 只换皮不换尺寸**（保留 `popup_size` 原样、只把纹理换成整图）

结果：小弹窗被 750×781 的整图撑糊 —— 整图方案天然要求尺寸固定，二者必须一起改。
