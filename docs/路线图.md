# 《大掌柜》复刻路线图

> 定位：**自娱自乐的单机复刻版**。目标不是做成运营游戏，是「像《叫我大掌柜》，但所有付费点直接通过」。
> 本文件只回答三个问题：**做到哪了、下一步做什么、什么不做**。
> 事实基准：2026-10-22，HEAD `d584beb`「晋升弹窗改造」，工作区干净；引擎基线 headless 通过。
> 维护：阶段目标变化才改本文件；每日进度改《系统看板》，不在这里记流水。

---

## 0. 结论先行

1. **现在不缺系统，缺一条被走通过的主线。** 40 个系统、4.2 万行代码、315 次提交，但没有一条「新号 → 第一家店 → 第一个门客 → 第一次赚速翻倍 → 通关」的路径被真正跑通、验收过。府邸首屏还摆着 6 个「后续版本开放」的死入口。
2. **下一步不是继续加系统，是 M1 垂直切片**：用 30 分钟的新手体验，把「开店 → 招人 → 赚速 → 关卡 → 离线收益」串起来。这一段不通，后面铺得越多越像 demo 堆。
3. **氪金改造不用重写。** 代码里 `do_recharge()` 本来就是免费的（点一下白给 10 倍元宝 + VIP 经验），缺的是收口：一键满 VIP、礼包 0 元宝、首充直领、一个 GM 面板。这是 M0 半天到一天的活。

## 1. 原作拆解与复刻边界

### 1.1 原作的核心循环

```
挂机赚速（商铺+门客） → 银两/元宝 → 升商铺、招门客、养徒弟
        ↑                                      ↓
   排名/资源/新玩法  ←  关卡、商战、商会验证战力
```

付费点全部插在**时间**和**概率**上：加速、抽卡、礼包、VIP 门槛、限时活动。复刻版要做的，就是把这些闸门一个个拆掉，同时保留「养成 → 变强 → 验证」的节奏。

### 1.2 五条内容线

| 线 | 内容 | 仓库对应 |
|---|---|---|
| 经营线 | 20 家商铺、钱庄、六店（钱庄/客栈/医馆/药铺/酒肆/酒坊）、妙音坊、庄园、垂钓、促织 | `shop_system` + 六店各自 system + `manor/fishing/cuzhi` |
| 养成线 | 门客（等级/资质/技能/天赋/风姿/信物/服装/守护灵/魂力/命盘）、挚友、徒弟 | `hero/talent/costume/guardian/token/fengzi/soul/soulpower/mingpan/xiangfang/friend/apprentice` |
| 验证线 | 关卡、商战、商会 BOSS | `stage/war/guild` |
| 收集线 | 藏品、图鉴、珍兽、服装 | `collection/beast` |
| 社交线 | 商会、好友、师徒、联姻 | `guild/haoyou/apprentice` |

### 1.3 付费点 → 免费方案总表

| 原作付费点 | 原作作用 | 本作改法 | 现状 |
|---|---|---|---|
| 充值（元宝） | 硬通货 | 充值页改「领取元宝」，点一次白给 | 逻辑已免费，UI 还叫「充值」 |
| VIP | 门槛 + 返利 | 一键满级；VIP 奖励一键全领 | 要充很多次才满，门客/挚友被 VIP 锁 |
| 特惠礼包 | 限时促销 | 0 元购买 | **已免费**（`buy_special_pack`） |
| 商城礼包 | 元宝回收 | 0 元宝领取 | 还扣元宝 |
| 抽卡 | 概率付费 | 券免费补满 / 消耗 0，保底保留 | 券来源少 |
| 首充 | 首付费钩子 | 新档直接可领 | 要`vip_exp>0` |
| 月卡/基金/战令 | 持续付费 | **不做付费版**；要做就做免费签到 | 不存在，无需改 |
| 限时活动 | 付费主战场 | 不做轮换，最多 1 个常驻 | 不存在 |
| 广告 | 复活/加速 | 不做 | 不存在 |

### 1.4 复刻范围矩阵

- **P0 主线必经**（不做就没法通关）：商铺、门客、关卡、离线收益、招募、钱庄、至少 2 家六店。
- **P1 主线增益**（做了明显更好玩）：天赋、技能、挚友、徒弟/联姻、珍兽、藏品、商战、商会。
- **P2 收藏支线**（有空再说）：服装、风姿、信物、守护灵、魂力、命盘、厢房、垂钓、促织、庄园、妙音坊、招商、游历、行善、抽奖。
- **P3 明确不做**：限时活动轮换（逐鹿隋唐/狩猎/夺魁）、真人排行榜、实时 PvP、公会战、配音、多语言、内购/广告 SDK、服务端反作弊、架构重写。

> 判据只有一句：**它是否让「30 分钟到 30 小时」的主线更好玩。** 不服务的，进停车场（§6.4）。

### 2.2 五个结构性问题

1. **入口即迷宫。** 府邸首屏 = 8 张地图牌 + 8 个顶网格按钮 + 3 项侧边抽屉，其中 6 个入口点了只弹「后续版本开放」；全游戏实测 **9 个死按钮 + 6 处占位文案**（见 §2.5）。新玩家第一眼看到的是一堆死按钮，不是「下一步该干嘛」。
2. **数值没有「下一个目标」。** 商铺曲线、关卡难度、门客养成成本各自独立配置，没有一张「玩家 7 天曲线」把它们串起来。玩家不知道下一步，开发者也不知道该调哪。
3. **机制够厚，表现层欠账。** 35/40 系统的主循环已经闭合，但 8/40 页面场景化、0 音频、0 引导、0 排行榜。玩家感知的「像不像」，一大半在表现层——这是目前最大的落差，也是 M5 要还的债。
4. **存档是单点。** 40 个系统共享一个扁平 JSON，加字段靠 `has()` 兜底；没有结构版本号。现在能跑，但越往后越不敢动老档。
5. **验收闭环缺失。** 档案里大量「已交付待实测」，没有「实测通过/不通过」的回写。结果是不知道地基哪块是空的——这次审计就是为了把这块补上。

### 2.3 系统看板

40 个系统的逐项状态、缺口、证据，见 [系统看板](系统看板.md)。摘要：**可玩 35 / 半成品 5 / 骨架 0 / 占位 0**；5 个半成品都是「资源花出去、效果没落地」的断头，不是没做。

### 2.4 三个待拍板的数值问题（本次实测）

1. **商铺解锁表的终点和主线终点对不上。** `SHOP_UNLOCK_TABLE` 最高一档 `yao_chang: 20000` 关。如果 v1 按 100 关通关，第 6 家店（130 关）之后永远开不出来；如果终点就是 20000 关，那 100 关通关的标准要改。**先拍板 v1 终点，再决定压表还是改标准。**
2. **关卡消耗与 Boss 门槛没有验算记录。** 贸易消耗 `500 × 关^3.2`（100 关约 12.5 亿铜钱）；Boss 门槛是门客总赚速 `50 × 关^2.3`（100 关约 199 万/秒）。这两个数单位不同、不能直接比，但**它们和商铺赚速、门客成长是否对得上，没人算过**。M2 必须代 Lv1 / 20 / 50 / 100 各算一遍。
3. **VIP16 要 1000 万元充值经验。** 点一次 648 才 6480 经验，满级要点 1.5 万次。这是「必须一键满级」的硬证据，不是玩家懒。

## 3. 「做完」的定义

没有终点的项目一定烂尾。先定一个可以改的终点：

### 3.1 通关标准 v1

- **经营**：20 家商铺全开，其中 10 家满级（20 级）；钱庄满级。
- **主线**：关卡 100 关通关（终点关数待拍板，见 §2.4）；每 10 关至少解锁 1 个新东西（店/门客/系统）。
- **养成**：门客图鉴 ≥ 60%，主力 5 人满资质、满技能。
- **验证**：商战 50 胜；商会 5 级。
- **收集**：藏品套装 ≥ 50%；珍兽 ≥ 10 只。
- **结局**：触发「汴梁首富」结算页，可开二周目。

### 3.2 单个系统的 DoD（完成定义）

一个系统只有同时满足四条才算「完成」，否则一律算半成品：

1. **进入**：有明确入口，且入口在主线进度到点时才出现（不是一开始就摆着）。
2. **操作**：核心操作有即时反馈（数值变化 + 飘字/音效 + 存档）。
3. **产出**：产出接入全局赚速/资质/资源，不是孤立数字。
4. **毕业**：有明确的「练到头」状态和下一个去处。

### 3.3 三条验收线

- **机制线**：上面四条 DoD。
- **数值线**：每条曲线代 Lv1 / 20 / 100 / 600 验算，且与关卡难度对齐。
- **表现线**：加载态 / 空态 / 满态 / 错误态齐全；关键操作有音效；页面无死按钮。

## 4. 路线图（B + M0–M6）

> 排序原则：**先补底座，再让一个人能从头玩 30 分钟，再让他能玩 30 小时，最后才让它好看。**
> 每个阶段必须验收通过才开下一个；没通过就继续修，不跳。

### B 底座（约 3 周，先于 M0）

**目标**：把「每个玩法自带一套小引擎 + 中心公式手改」改成「能力复用、新玩法只填配置/页面」。

交付（详细契约见 [底座改造-Kimi交接](底座改造-Kimi交接.md)）：

- **B1 Shop 加成注册表**（0.5–1 天）：照抄 `hero_data._bonus_registry`，14 项链改遍历；数值快照逐字节一致。
- **B2 Accrual 收益罐原语**（2–3 天）：一个类接管时间戳结算；先迁客栈、酒肆。
- **B3 页面壳 + MedalTrack**（约 1 周）：先做 2 天 [FairyGUI spike](UI路线-FairyGUI-spike.md)；通过则换 UI 层，不通过则 `BaseView` 补顶栏/页签/列表/空态。勋章先并 2 套。
- **B4 主线解锁设计**（不写代码）：`quests.json` + feature gate，M1 实现。

验收：新增一个系统从「改 7 处」降到「≤3 处」（配置/系统/页面），且不碰 `shop_system`、不碰 `game_data` 状态区。

不做：任何新玩法、任何 UI 美化、任何存档结构变更。

### M0 定盘（3–5 天，B 底座之后）

**目标**：把「开发环境」变成「能反复试玩的游戏」。

交付：
- 冷启动直进：登录门改「开始游戏」一键（云存档变可选），3 秒内进府邸。
- GM 面板 v1（F1）：加铜钱/元宝/蓝图/声望、满 VIP、解锁全门客/挚友、清 CD、跳 24h、重置档、存档快照/回滚。
- 《系统看板》《路线图》《想法池》建起来（已完成）。
- `AGENTS.md` §6 同步到 `d584beb`，并挂上路线图/看板指针（本次已完成）。

验收：双击启动 → 3 秒进府邸；F1 能一键造出「开服 7 天」的档；看板每行有状态和证据。

不做：任何新玩法、任何 UI 美化。

### M1 新手 30 分钟（1–2 周）

**目标**：一个没玩过的人，不查攻略、不卡住，走完第一段。

交付：
- 府邸首屏瘦身：只留 4 个活入口（商铺 / 门客 / 关卡 / 招募），其余收进「更多」；死按钮先隐藏。
- 7 步引导：开店 → 雇店员 → 招门客 → 派门客 → 升第一级 → 打第 1 关 → 领离线收益。
- 初始资源与首日目标（`QuestSystem` 接主线，按 B4 设计稿实现；`goal_system` 只留挚友目标）。
- 首次离线收益弹窗（回来先看到「你赚了 X」）。

验收：新档 30 分钟走完 7 步，开 3 家店，赚速 ≥ 1000/秒，全程 0 次「不知道点哪」。

不做：支线、收集、社交。

### M2 经营闭环（2–3 周）

**目标**：让「开店 → 赚钱 → 开下一家店」转起来。

交付：
- **重排 `SHOP_UNLOCK_TABLE`**：按拍板后的 v1 终点压缩（若 100 关，则每 5 关开 1 家）；`SHOP_ORDER` 顺序即开店顺序。
- **重算关卡曲线**：代 Lv1 / 20 / 50 / 100 验算，保证每关 1–3 分钟、打不过时回去升店，而不是卡在等钱。
- 三货币闭环：铜钱（雇人）/ 蓝图（升级）/ 声望（关卡）各有稳定产出，不枯竭也不溢出。
- 六店 + 妙音坊 + 庄园 + 垂钓，每家至少 1 条产出接入主线赚速。
- 离线收益 8 小时上限的展示与领取体验。

验收：7 天档开 10 家店、满 2 家；每 10 关都有可见的新增益；没有「卡死等钱」超过 10 分钟。

不做：门客深层养成、PVP。

### M3 养成闭环（3–4 周）

**目标**：让「养门客」成为主线，而不是一堆并列的页签。

交付：
- 门客 10 条线（等级/资质/技能/天赋/风姿/信物/服装/守护灵/魂力/命盘）逐条定义：材料来源 → 消耗 → 收益 → 毕业。
- 每条线在主线进度上有解锁点，不一次性全开。
- 验算表：Lv1 / 20 / 100 / 600 四档，写进配置注释。
- 挚友 / 徒弟 / 联姻接入主线（不再是独立小游戏）。

验收：任一门客从 1 级养到满，每一步都有可见提升；材料不枯竭；玩家能说出「我现在在养谁、下一档要什么」。

不做：新系统。

### M4 支线收口（3–4 周）

**目标**：把「后续版本开放」清零。

交付：
- 逐个处理 §2.5 的 9 个死按钮 + 6 处占位文案：要么做，要么删，要么改成「已完成」态。
- 补完《系统看板》里的 5 个半成品：副业两币种产出、天赋七类效果、藏品 38 个效果、挚友无双技能、神话门客。
- 全游戏死按钮 = 0。

验收：玩家可见处 `后续版本开放` 出现次数 = 0；每个按钮点下去都有真实反馈。

不做：P3 清单里的任何东西。

### M5 表现层（持续，穿插）

**目标**：让 3 分钟录屏能发给朋友，不丢人。

交付：
- BGM 4 首（府邸/商铺/战斗/活动）+ UI 音效 20 个（点击/升级/开箱/过关/错误）。
- 动效：升级、开箱、过关、赚速跳字、页面转场。
- 场景化剩余 32 个页面（按「闹心程度」排序，不追求全量）。
- 弹窗皮肤收尾（costume / tavern / 5 个全屏页壳）。

验收：3 分钟录屏，朋友看不出是自制。

不做：配音、Live2D、3D。

### M6 终局（1 周）

**目标**：给游戏一个「打完」的时刻。

交付：
- 「汴梁首富」结局页 + 统计（用时/门客/商铺/收藏）。
- 图鉴 / 成就 / 二周目（继承部分收藏，难度+1）。
- 通关后解锁自由模式（全系统开放 + 爽玩资源）。

验收：能通关；通关后想再开一局。

## 5. 氪金 → 免费

### 5.1 现状盘点

| 项 | 代码现状 | 玩家感受 |
|---|---|---|
| 充值 | `do_recharge(6/30/98/...)` 白给 `amount*10` 元宝 + VIP 经验 | 要假装付钱，点 6/30/98，仪式感多余 |
| 特惠礼包 | `buy_special_pack` 不扣钱，白给 | 已经是免费 |
| 商城礼包 | 扣元宝 | 元宝能白拿，等于免费但多一步 |
| VIP | 靠充值经验，16 级要 1000 万元 | 门客/挚友被 VIP 锁，要刷很多次 |
| 首充 | 要 `vip_exp>0` 才能领 | 得先点一次充值 |
| 抽奖 | 券或元宝 | 券不够就卡住 |

### 5.2 爽玩模式（`sandbox_mode`，新档默认开）

在 `game_data` 加一个存档字段 `sandbox_mode: bool = true`，开时：

1. **开局**：元宝 100 万、铜钱 10 万、蓝图 1000、声望 100。
2. **充值页**改「领取元宝」：点一次 +10 万元宝，无 CD；VIP 经验每次 +1000 万，10 次满级。
3. **VIP 面板**加「一键满级」「一键全领」——不靠点充值刷 1.5 万次。
4. **商城礼包**：0 元宝。
5. **抽奖**：每日免费 10 连；券不足时 0 元宝补。
6. **首充**：新档直接可领。
7. **设置里可关**：关掉回到原曲线（方便对比数值/怀旧）。
8. **老档兼容**：进游戏弹一次「是否开启爽玩模式」，默认开；选择写进存档，之后可在设置里改。

关掉时一切照旧，不改任何原有公式——这样「免费」是一层开关，不是散落在 40 个系统里的 if。

### 5.3 GM 面板（F1）

四页：

- **资源**：+铜钱 / +元宝 / +蓝图 / +声望 / +道具（按 id 搜索）。
- **养成**：满 VIP / 解锁全门客 / 解锁全挚友 / 门客满级 / 商铺满级。
- **时间**：清 CD / 跳 1h / 跳 24h / 强制离线结算。
- **存档**：快照 / 回滚 / 导出 / 重置。

这不是作弊，是**测试加速器**：没有它，每次验证「7 天档」都要真等 7 天。

### 5.4 取舍：钱免费，时间保留

全免费有一个副作用：**所有消耗失去意义，游戏 3 小时就腻**。所以建议：

- **钱免费**（元宝/铜钱/礼包/抽卡）——这是用户要的「氪金直接通过」。
- **时间保留**（离线收益上限、每日次数、CD）——这是游戏的节奏，拆了就没得玩。
- 如果哪天想纯爽，GM 面板的「跳 24h」就是开关。

## 6. 工作方式（治「想到哪做到哪」）

### 6.1 三份文档

| 文档 | 作用 | 更新频率 |
|---|---|---|
| `docs/路线图.md`（本文件） | 阶段、验收、边界 | 阶段变化时 |
| `docs/系统看板.md` | 40 行状态 + 下一步 | 每个任务完成后 |
| `docs/想法池.md` | 新想法暂存，不进当前阶段 | 想到就记 |

### 6.2 五条铁律

1. **一次只做当前里程碑的一个任务**，任务 ≤ 1 天；做不完就拆。
2. **每个任务必须有验收动作**：能点出来、能截图、能量化。写不出验收动作的任务，不是任务。
3. **做完真机跑一遍**，结果回写看板（通过 / 不通过 / 原因）。「已交付待实测」不算完成。
4. **里程碑未验收，不开下一阶段的新系统**。想加，进想法池。
5. **每周日 30 分钟复盘**：看板过一遍，只调优先级，不加系统。

### 6.3 一周节奏

- 周一：从看板挑本周 3–5 个任务，写进当周清单。
- 周二–周五：每天 1 个任务，做完回写。
- 周六：整合 + 真机长跑（至少 30 分钟不崩）。
- 周日：复盘 + 下周排期；想法池过一遍，只捞和当前里程碑相关的。

### 6.4 停车场

任何「诶这里加个 XX 会更好」的念头，先写进 `docs/想法池.md`，格式：

```
- [ ] 想法：xxx
  - 为什么想要：
  - 服务哪个里程碑：
  - 最早可做：M?
```

**不写进池子的想法，一律不做。** 这是治「想到哪做到哪」的唯一硬约束。
